aat

The aat command line

View as Markdown llms.txt

The aat commands, flags, and exit codes.

Every command and flag of aat, matching aat --help and each command's --help. crates/aat/tests/docs.rs fails when this page misses a command.

Naming an automation

Where a command takes <NAME>, give one of:

  • its name, such as watch-inbox;
  • user/<name> or repository/<name>, to pick a scope when both have one with that name;
  • a prefix of its name that matches only one automation;
  • its full automation key, <scope>:<root path>:<name>, as aat check <name> and aat list --json print it.

aat refuses anything else with one line (exit 2) that names the keys it could be, or says no automation named "x" — aat list shows them.

Exit codes

CodeMeans
0ok
1usage or error: an unknown command or flag, a missing argument, a config.toml aat refuses, a command that could not finish
2refused: the request was understood and declined, with one line saying why (not armed, is not running, an unknown name)
10aat run only: the run was skipped
20aat run only: the run failed
30aat run only: the run was aborted

Refusals and errors go to standard error, one line each. Answers go to standard output.

Commands

aat

aat
aat tui [--fake]

Opens the terminal UI. aat with no command does the same. --fake shows demo data without touching real automation state; editing a demo creates a temporary sample file. The README and the UI's own ? page list the keys.

For e, the UI opens VISUAL, then EDITOR, falling back to notepad on Windows and nano then vi elsewhere. Environment variables lists the others it reads.

aat list

aat list [--json]

Every automation, grouped by scope (USER, then each REPOSITORY root), with its state, its trigger, when it next runs or checks, and the agent CLI it runs through. An automation that needs something from you gets a second line saying what, such as not armed — aat arm watch-inbox or also armed in pa — it would run twice; pa disarm watch-inbox.

FlagDoes
--jsonPrints every automation as one JSON array. See JSON outputs.

aat check

aat check [NAME]

Re-checks automations against the specification and this machine.

Without a name, it prints one line for each automation: its name, its state and, when it is not armed, why.

With a name, it prints everything about one automation: its state and every problem, its scope, folder, automation key, agent CLI, timeout, digest, the interpreter each script runs with, its schedule with its stagger and next three scheduled instants, its watch and last watch check, the run going now, the last run, whether pi-automations has it armed too, and then its consent preview: the exact agent command, model, hooks, and the files consent is pinned to.

aat check exits 0 whatever the state. It exits 2 only when the name matches nothing or more than one automation.

aat arm

aat arm [-y | --yes] NAME

Prints the consent preview, then asks Arm <name>? [y/N]. Only y or yes arms it.

FlagDoes
-y, --yesAccepts the preview without asking. Needed when standard input is not a terminal, or aat arm refuses with not armed — re-run with --yes to accept the preview.

Consent is pinned to the content hashes of AUTOMATION.md and every script it names. Any change turns the automation off until you arm it again. Consent to a repository automation also expires after consent-expiry (see CONFIG.md). Arming a repository automation registers its repository root, so aat list, the UI and the watcher find it from any folder.

aat refuses an invalid or disabled automation (exit 2). For one that is already armed, it says so and exits 0. When pi-automations has the same automation armed, the preview starts with ! also armed in pi-automations — it would run twice, followed by the pa disarm command that turns it off there.

aat disarm

aat disarm NAME

Withdraws consent on this machine. The automation stays listed, off, and does not run.

aat enable and aat disable

aat enable NAME
aat disable NAME

Set enabled: true or enabled: false in a user automation's AUTOMATION.md, keeping any consent it had. They refuse a repository automation (exit 2): edit and commit its file instead, or aat disarm it to keep it off on this machine.

aat run

aat run [--detach] NAME

Runs one automation now, by hand (trigger manual). It starts aat fire for the automation, prints the run's live events as they arrive (tool calls, steps, updates, the answer), then the run record. It exits with the run's code (see Exit codes).

FlagDoes
--detachStarts the run in the background, prints <name> started and returns 0. Follow it with aat log or in the UI.

Refused (exit 2) when the automation is not armed, is already running, or has no manual: true under on:. A run that fails shows a desktop notification (see Notifications).

aat stop

aat stop NAME

Asks the run going now to stop. Its post hooks run, then it records aborted. Refused (exit 2) when nothing is running.

aat log

aat log [-n N] [--json] NAME
aat runs [-n N] [--json] NAME

The automation's runs, oldest of the last N first: when each ran, its trigger, outcome and reason, the agent CLI, its hooks, its notes with their links, and its message. aat runs is the same command.

FlagDoes
-n NHow many runs. Default 10.
--jsonOne run record per line (JSON Lines), exactly as stored in runs/<name>-<hash>.jsonl in the state folder.

aat watch

aat watch pause NAME
aat watch resume NAME

aat watch pause stops an automation's watch checks until aat watch resume. Its schedule and manual runs still work, and the file is not changed. Refused (exit 2) for an automation with no on.watch.

aat agent

aat agent list
aat agent default CLI
aat agent set NAME CLI

CLI is one of pi, copilot, claude, codex, gemini, opencode (see AGENTS.md).

CommandDoes
aat agent listEvery agent CLI aat knows, with the version and path found on this machine, or why it was not found. * marks the default.
aat agent default CLISets the CLI every automation runs through unless it has its own (default-agent in config.toml). none clears it.
aat agent set NAME CLIRuns one automation through CLI ([automations."<key>"] agent). default goes back to the default.

An unknown CLI name exits 1. The agent CLI is part of the consent preview: changing it does not change consent, but the next aat check shows the new command.

aat tick

aat tick [--json]

One tick: clears run locks whose process is gone (recording aborted), fires every schedule that is due, applies the grace period and catch-up, records missed instants, then runs the watch checks that are due and starts a run when one finds new work. Each scheduled run starts after its stagger. The watcher runs this once a minute; run it by hand to see what is due now.

It prints one line, such as fired 1 · missed 0 · swept 0, with failed N, skipped N and checked N added when they are not zero, then one line for each run that could not start and each problem. A tick that finds another tick running does nothing and says so. By hand from inside a repository, it also reads that repository's automations, armed there or not yet registered.

FlagDoes
--jsonWhat the tick did as one JSON object.

aat serve

aat serve

Ticks once a minute in the foreground until Ctrl-C. Use it where you cannot register the watcher, such as in a container. It refuses (exit 2) while the watcher is registered for this state folder, since two clocks would then tick at once.

aat watcher

aat watcher start [--json]
aat watcher stop [--json]
aat watcher status [--json]

The watcher, which fires schedules and runs watch checks, is an OS job that runs aat tick once a minute for one user and one state folder. Without it or aat serve, no schedule fires and no watch check runs.

OSJob
WindowsThe Task Scheduler task agent-automations\tick. It runs hidden, with no console window.
macOSThe LaunchAgent io.agentautomations.aat.tick in ~/Library/LaunchAgents.
LinuxThe systemd user timer aat-tick.timer, or a crontab line marked # aat-tick (aat watcher) when there is no systemd user session. A user timer stops at logout unless loginctl enable-linger is on.
CommandDoes
aat watcher startRegisters the job, asks the OS to run it at once, and waits up to 90 seconds for its first tick. Refused while aat serve ticked in the last two minutes.
aat watcher stopRemoves the job.
aat watcher statusWhether the watcher is on, off, late (registered but not ticking), or off with aat serve ticking instead, and when it last ticked.
FlagDoes
--jsonThe answer as one JSON object.

The job carries AAT_HOME, PATH, HOME and a few other variables from the shell that ran aat watcher start, never a credential, and runs the aat that registered it. When that aat is gone, the job removes itself. Scheduled runs do not read your shell profile: sign each agent CLI in once, and set [agents.<cli>] path in config.toml when the CLI is not on that PATH.

The job appends what its ticks print to logs/tick.log in the state folder, and a quiet tick prints nothing. Each run a tick starts appends its output to logs/<name>-<hash>.log, where the <hash> tells apart automations with the same name.

Notifications

When a run's outcome is failed, whatever started it, aat shows a desktop notification titled <name> failed. Its text is the error or reason and how long the run took, such as claude exited 1: rate limited (after 2m). aat shows a toast through PowerShell on Windows, and uses osascript on macOS and notify-send on Linux. If a notification cannot be shown, aat drops it; the run and its record do not change.

notify-on-failed = false in config.toml turns notifications off. AAT_NO_NOTIFY set to any value turns them off for that process and every run it starts.

Environment variables

VariableDoes
AAT_HOMEThe state folder, instead of the per-OS one in the README.
AAT_NO_NOTIFYSet to any value: no desktop notification when a run fails.
AAT_THEMElight or dark: the UI's colours, when the terminal does not say.
AAT_ASCII1: the UI draws with ASCII only.
NO_COLORSet: the UI draws without colour.
VISUAL, EDITORThe editor e opens in the UI.
FM_BINThe fm executable that draws flowcharts, when fm-path is not set in config.toml.
PI_AGENT_DIRWhere pi-automations keeps its state, for the "also armed in pa" warning. Default ~/.pi/agent.
XDG_STATE_HOMEOn Linux, the parent of the state folder.
AAT_RUN, AAT_NODE, AAT_STATE_DIRSet by aat for a run's body and hooks; see Inside a run.

Inside a run

The body, every hook and everything they start get AAT_RUN (the run id), AAT_STATE_DIR and, on a tracked run, AAT_NODE (body, pre0, …). With those set, these commands report progress. They skip discovery, so they answer fast from any folder.

CommandDoes
aat step <node> [--status active|waiting|done|failed|skipped] [-m text]Sets one node. active by default.
aat next <to> [--from <node>] [-m text]Finishes <node> and starts <to>. --from defaults to AAT_NODE, else the one running node. In a flow: strict run, the move must follow an arrow of the flowchart.
aat say <text> [--node <node>] [--request-id <key>]Adds an update to a node.
aat note <text> [--link "label=https://…"]… [--request-id <key>]A note on the run record, with the links it published.
aat message <text> [--link "label=https://…"]… [--request-id <key>]The run's one message for its reader. The last one wins.
aat statusWhere the run is: every node, the arrows taken, the notes, the message.

Name a node by its id, or by its exact label when no other node has that label. Repeating the same step or next changes nothing the second time; --request-id makes say, note and message happen once however often you retry them. -m is short for --message. Every in-run command takes --json, and --run <id> to name a run when AAT_RUN is not set.

They exit 0 when they made the change, 1 for a usage error (USAGE) or a link that is not http or https (BAD_LINK), and 2 when refused: NO_RUN, UNKNOWN_RUN, RUN_CLOSED, NO_CHART, UNKNOWN_NODE, AMBIGUOUS_NODE, NO_ACTIVE, AMBIGUOUS_ACTIVE, NOT_AN_EDGE, LOCK_TIMEOUT, IO. These codes mean what they mean in pi-automations' reporting.

aat fire

aat fire --key KEY --trigger manual|schedule|watch [--scheduled-for ISO] [--late]

Hidden from aat --help. It runs one automation by its automation key, in this process, and exits with the run's code (0, 10, 20, 30), or 2 when it refuses without writing a record. aat run, the UI and the watcher start it for you. --scheduled-for is the scheduled instant a schedule run is for, and --late marks a run that started after its grace period.

JSON outputs

CommandPrints
aat list --jsonOne JSON array, one object per automation: key, name, scope (user, repository), dir, state (invalid, disabled, off, armed), reason, problems, automation (the parsed frontmatter and body, null when invalid), agent, effective_timeout_ms, next_fire, next_check, watch (the last watch check), watch_paused_at, running (the run going now), flow, last (the last run's outcome, at, reason, duration_ms), also_armed_in_pa. Times are ISO 8601.
aat log --jsonOne run record per line, oldest first, as stored. Every record has id, key, name, scope, root, trigger, late, recordedAt and outcome; when they apply, also scheduledFor, startedAt, endedAt, reason, error, agent, model, timeout, hooks, output, session, chart, steps, taken, notes, message, count (instants a missed record covers) and pid.
aat tick --jsonOne object: locked (another tick was running, so this one did nothing), considered (armed automations with a schedule), and the automation keys it fired, found missed, skipped because a run was still going, swept (abandoned run locks), left waiting for their stagger, and checked (watch scripts run); failed (each a key and why it could not start) and problems (one line each).
aat watcher status --jsonOne object: state (on, off, late, serve), summary (one line), lines (what aat watcher status prints), record (what was registered, or null), lastTickAt, lastTickBy (job, serve, cli).
aat watcher start|stop --jsonOne object: ok, and lines, what the command prints.
in-run commands with --jsonOne object on standard output, ok or not: {"ok":true,"changed":true,"warnings":[],"data":{…}}, or {"ok":false,"error":{"code":"UNKNOWN_NODE","message":"…","suggestions":["…"]}}.
